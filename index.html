Scope of this tool. Implements Section 7 (Design Traffic / ESA calculation); the Section 11.8.3 pavement catalogue for lightly-trafficked granular pavements with thin bituminous surfacing (design traffic ≤ 3×106 ESA); the Section 8.3.1 empirical design chart (Figure 8.4) for granular pavements with thin bituminous surfacing, covering the wider 105–108 ESA range — per §8.2.7 this chart gives a total granular thickness equivalent to the full mechanistic-empirical procedure (using a top granular modulus of 350 MPa), so it is used here as the practical, closed-form stand-in for that procedure; and the Section 9 minimum-requirement tables for rigid (concrete) pavements. It does not implement the fatigue/erosion nomograph procedure of Section 9.4 for heavily-trafficked rigid pavements — that requires specialist software and a qualified pavement engineer. Every figure in Tabs 1–3 and 5 is transcribed from the source PDF and cited by clause; verify against the original document for final design submissions. Tab 4 (Mechanistic-Empirical) is a separate, experimental addition: since §8.2 itself delegates the layered-elastic strain calculation to external software (AustPADS/CIRCLY) rather than providing the method, Tab 4 is an independently-built implementation of that general theory — not part of the official MPWT specification, unvalidated against MPWT-recognised software, and not to be used for a submission without an engineer's independent check. See the warning banner on that tab for details. Tab 5 (Overlay Design) implements Section 12.3, the empirical design of granular overlays for rehabilitating granular pavements (deflection testing, seasonal/device adjustment, characteristic deflection, and overlay thickness — fully closed-form, valid to 108 ESA). Section 12.4's mechanistic-empirical strengthening design (for pavements with asphalt/cemented layers) requires FWD deflection-bowl back-calculation software this tool does not implement on that tab; Tab 6 adds that back-calculation. Tab 6 (FWD Back-calculation) implements §12.4.4 — estimating the moduli of the existing pavement layers and subgrade by fitting a computed deflection bowl to measured FWD bowls — together with Appendix G (composite modulus, Equation G.1) and the §12.4.4 subgrade sublayering rules (Equations 12.5–12.7). It accepts multiple raw FWD data files, pasted data, or a single hand-entered bowl, and ships with the full 1,919-point NR7 PK424+000–522+000 survey from the uploaded FWD report. Like Tab 4 it is experimental and unvalidated against MPWT-recognised software, and back-calculation is inherently non-unique — see the warnings on that tab. Austroads alignment. Every criterion implemented here has been checked against Austroads AGPT02-26 Guide to Pavement Technology Part 2, Edition 5.2 (July 2026) — the parent document D3 102-2024 is adapted from. The criteria are unchanged; the three places where the parent guide has since been extended are set out in a reference table on Tab 4. D3 102-2024 remains the binding standard and is what every compliance verdict in this tool is measured against.

⚠️ Experimental — Unvalidated Against Reference Software

D3 102-2024 §8.2 does not itself provide the layered-elastic strain-calculation method — it explicitly requires "computer programs such as AustPADS" (§8.2, list of significant features) capable of modelling a multi-layer elastic pavement. This tab is an independent implementation of that general layered-elastic (Burmister-type, n-layer axisymmetric elastic) theory, derived and coded from first-principles continuum mechanics — it is not part of the official MPWT specification and MPWT has not reviewed or endorsed it.

What has been checked: the solver's stresses/strains match the closed-form Boussinesq single-layer solution to machine precision, and match a published 3-layer benchmark (Jones 1962 / cross-checked by Wang, Roesler & Guo 2011) to 4–5 significant figures. What has NOT been checked: there is no access to AustPADS, CIRCLY, or any MPWT-approved software in this environment to cross-validate real project inputs.

Scope limitation: this module evaluates the critical strain directly beneath the centre of a single circular wheel load only (on-axis). It does not implement multi-wheel (dual-tyre) superposition or the "between tyres" check shown in Figure 8.2 / Table 8.2 of the Specification — for many pavements the single-wheel, under-load case shown here is not the only location that needs checking.

Do not use these results for an MPWT submission or construction decision without independent verification by a qualified pavement engineer using MPWT-recognised software (e.g. AustPADS/CIRCLY).

Overlay Design — Rehabilitation of Existing Pavements

D3 102-2024 Section 12 — Overlays for Flexible Pavements.

Section 12 covers two distinct routes, depending on whether the existing pavement contains asphalt and/or cemented material:

  • §12.3 — Empirical design of granular overlays (implemented below): for existing pavements that are granular only (no asphalt/cemented layers), valid up to 108 ESA. Fully closed-form — deflection testing (Benkelman Beam or FWD) drives the required overlay thickness directly.
  • §12.4 — Mechanistic-empirical procedure (MEP) for strengthening treatments: required whenever the existing pavement contains asphalt and/or cemented material (asphalt overlays/inlays, major patching, stabilisation). This route requires back-calculating the existing layer/subgrade moduli from measured FWD deflection bowls — a specialist, iterative numerical process (§12.4.3–12.4.9) that needs dedicated back-calculation software (e.g. EVERCALC, MODULUS, or a CIRCLY back-calculation module). This tool does not implement back-calculation — see the guidance card at the bottom of this tab for how to combine externally back-calculated moduli with the Tab 4 mechanistic-empirical solver.
Confirm which route applies before proceeding: if the existing pavement includes any asphalt or cemented/stabilised layer, the §12.3 granular-overlay calculator below does not apply to it (§12.3.3) — go to the §12.4 guidance card instead.

On the overlay-thickness formula: D3 102-2024 provides Figure 12.3 as a design chart, not a closed-form equation. The Specification states the chart "is based on available field data that indicates a 6% reduction in deflection for each 25 mm of granular overlay thickness" (§12.3.3). §12.4 — Mechanistic-Empirical Strengthening (Asphalt/Cemented Pavements)

For existing pavements containing asphalt and/or cemented material — not computed by this tool.

§12.4's MEP mirrors the new-pavement mechanistic-empirical procedure already implemented in Tab 4 (§8.2), except the layer moduli for the existing pavement and subgrade must first be estimated from FWD deflection-bowl back-calculation (§12.4.4) — a trial-and-error numerical fitting process, typically run in dedicated software, that iterates layer moduli until the predicted deflection bowl matches the measured one. That back-calculation is implemented in Tab 6 (FWD Back-calculation), together with Appendix G's composite modulus and the §12.4.4 sublayering rules (Equations 12.5–12.7). What remains out of scope even there is the conversion of back-calculated moduli into design moduli: temperature adjustment to WMAPT (Appendix F), seasonal moisture (§12.4.6), the modulus reduction factor for future fatigue damage (Equation 12.13), and the presumptive cracked-material properties of Table 12.7.

How to bridge to Tab 4: run Tab 6 to back-calculate the existing layer and subgrade moduli, adjust them for temperature, seasonal moisture and future fatigue damage per §12.4.5–12.4.8, then use Tab 6's "Load this structure into Tab 4" button — they become the lower layers of a Tab 4 layer stack, with the proposed new overlay layer(s) added on top — Tab 4's solver already supports an arbitrary n-layer stack and evaluates critical strains against the same Section 5/6 fatigue criteria this rehabilitation design also uses. Two points from §12.4.1 to carry across: existing bound (asphalt/cemented) layers are normally assumed to have negligible remaining fatigue life, so only the fatigue life of the new materials is usually checked; and reflective cracking risk from cracked material below is a real concern — new-pavement design uses 175 mm of sound asphalt cover over cemented/RCC/LMC material as its benchmark for that risk.

Do not substitute the §12.3 granular-overlay calculator above for pavements containing asphalt or cemented material, and have any §12.4 strengthening design — including anything produced via Tab 6 — reviewed by a qualified pavement engineer with MPWT-recognised back-calculation software.

⚠️ Experimental — Back-calculation Is Non-Unique by Nature

D3 102-2024 §12.4.4 describes back-calculation as "a methodical trial and error approach used to determine the combination of layer moduli such that the predicted deflection bowl best matches the measured deflection bowl" — it prescribes no algorithm and delegates to external routines. This tab is an independent implementation: a Levenberg–Marquardt fit in log-modulus space over the same n-layer axisymmetric elastic forward model as Tab 4, extended to compute the full surface deflection bowl.

What has been checked: the off-axis surface-deflection solver reproduces the exact closed-form Boussinesq half-space solution (elliptic-integral form) to ≈0.01% at every sensor offset, and on synthetic noise-free bowls the optimiser recovers the true moduli to 4 significant figures from any starting seed. What has NOT been checked: no AustPADS, CIRCLY, EVERCALC or MODULUS is available here to cross-validate against on real project data.

Back-calculation is fundamentally non-unique: different modulus combinations can reproduce the same bowl to within measurement error, and the answer depends strongly on layer thicknesses you supply. Treat every result here as a starting point for engineering judgement, never as a measured value.

Step 1 — Load FWD Deflection Data

§12.4.4 — back-calculation is performed on measured FWD deflections without correction for temperature or seasonal moisture; those influences are considered later, when design moduli are determined (§12.4.6).
Select one or more files — each is parsed independently and the records are pooled, with the source file and lane recorded per record. Native KUAB .fwd files are read directly (UTF-16 and all), including the instrument's own metadata: plate radius, sensor offsets, lane (LHS/RHS), pavement temperature, the KUAB Emod column, and the operator/QC comment lines — so a "deflection is not decreasing" flag raised in the field follows the record through to the analysis. Plate radius and sensor offsets are filled in from the header automatically. CSV / TSV / TXT files also work: the parser looks for a station/chainage column, a load column, and one deflection column per sensor, auto-detecting common header names (PK / Distance / Chainage / Station, Force / Load, D0…D8 or D1…D9).

Back-calculated Moduli
Read the two fit numbers together. The badge is the conventional per-sensor relative RMS — the figure practitioners and reviewers quote, where below 2% is good, 2–5% usable, above 5% poor. It is, however, dominated by the smallest readings: a 5 µm miss on a sensor reading 25 µm scores as 20%, while the same 5 µm on the 500 µm centre reading scores as 1%. The second line gives the RMS residual in µm and as a percentage of D₀, which says how well the bowl is reproduced in absolute terms. A large badge percentage with a small µm/D₀ figure means noisy outer sensors, not a wrong model — the moduli are still usable, with judgement. Both numbers large means the structure you assumed genuinely cannot produce this bowl: change the thicknesses, add or remove a layer, or exclude a misreading sensor above.
